# /idea: 作業の引っかかりを記事のネタとして残す

ネタ帳は `/Users/kowwwwji/ghq/github.com/kowwwwji/zen/notes/ideas.md`。今いるリポジトリに関係なく、このファイルに追記する。

書くのは「調べる前の引っかかり」であって、記事の下書きではない。半年後に行を読んで「何に引っかかって、誰に向けて書くつもりだったか」が思い出せれば足りる。

## 手順

### 1. ネタを 1 行にまとめる

引数があればそれを元にする。なければ、このセッションでやったことから起こす。たとえば AeroSpace と JankyBorders を整備した直後なら、「設定したこと」ではなく「何に困って、どう決めたか」が種になる。

1 行に入れるもの:

- **引っかかり**: 何に困った、何が分かりにくかった、何を決めたか。「〜した」という作業報告ではなく、読者が同じ場面で欲しがる判断や答え
- **誰向け**: その場面にいる人を 1 句で
- **出どころ**: repo 名とファイルやコマンド、日付。後で Scrap やノートに移すときの手がかり

形式:

```markdown
- <引っかかりと答えの要点>。<誰向け>（<repo や path、コマンド>、<YYYY-MM-DD>）
```

例:

```markdown
- AeroSpace でフォーカス中のウィンドウが分からなくなり、JankyBorders で枠を付けた。設定の最小構成と、aerospace の on-focus-changed から borders を呼ぶ方法。タイル型 WM を macOS で始めた人向け（dotfiles: dot_config/aerospace/aerospace.toml、2026-10-30）
```

### 2. 追記する

ファイルを読み、末尾のリストに行を足す。同じ引っかかりの行がすでにあれば、新しい行を足さずにその行へ出どころを追記する。見出しや「公開済み」の区分は作らない。1 つのフラットな一覧のままにする。

### 3. コミットする

zen リポジトリで `notes/ideas.md` だけをコミットする。他の変更は巻き込まない。push はしない。

```sh
git -C /Users/kowwwwji/ghq/github.com/kowwwwji/zen add notes/ideas.md
git -C /Users/kowwwwji/ghq/github.com/kowwwwji/zen commit -m "Add idea: <要点を英語で短く>"
```

### 4. 追記した行を見せる

追記した 1 行をそのまま表示する。直したければその場で直せるように。

## やらないこと

- 調査や記事の下書きを始めない。ネタ帳は入口であって、調べるのは Scrap か `/note` の仕事
- 今いるリポジトリのファイルを変更しない
- zen の `notes/ideas.md` 以外を変更しない。push しない
